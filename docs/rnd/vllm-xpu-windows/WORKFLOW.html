Why this reopens vLLM

The SYCL-vs-Vulkan program parked vLLM until OMEN ran Linux. SystemPanic/vllm-windows is a native Windows port — but a CUDA one (README: "CUDA 13 + Blackwell GPU support on Windows", NCCL multi-GPU; no XPU/oneAPI/SYCL; Intel question #31 unanswered). Its value for us is the Windows build work: setup.py accepts Windows, MSVC build, winloop, spawn-only workers. Upstream vLLM's XPU platform is pure Python + torch-xpu + triton-xpu + one out-of-tree SYCL kernel package. Nobody had combined the two. OMEN already had oneAPI 2026.1 and torch-xpu Windows wheels that see both B70s. Amended reopen condition: a native Windows build path exists.

The ladder

L0 Desk done

Port is CUDA-only; assembly path named; XCCL wall verified (is_xccl_available() == False, no ccl in the toolkit); per-card shape.

L1 Env pass

torch 2.13.0+xpu + triton-xpu 3.7.2 on Python 3.12; both B70s (31.2 GB); a Triton kernel executes on xpu:0 once a C compiler is on PATH (run.cmd); fp16 4096³ matmul 37 TFLOPS.

L2 Kernels — basic pass

vllm-xpu-kernels 0.1.14.1 built with icx.exe on Windows after nine loud refusals (icpx vs icx driver, /FI for the forced include, backslash paths, uint, Level Zero SDK for ze_loader.lib, link libraries). 78-line patch on branch windows. rms_norm / fused_add_rms_norm / silu_and_mul / rotary match torch on the B70.

L2-full Kernels — FA2 + MoE + _xpu_C needs cue

SYCL-TLA attention/grouped-GEMM + static oneDNN. Estimate 30–60 min of compile. Gate for the production model family (MoE and int4 paths both need these).

L3 Engine pass

vllm serve Qwen/Qwen3-0.6B --attention-backend TRITON_ATTN --enforce-eager on :8097. Seven launch refusals fixed one at a time (hard MoE imports, a stray import uvloop in the fork's deprecated entrypoint, a vllm/ directory shadowing the package, hung parents holding ZMQ :29550, memory shared with production, FA2 selected by default). gloo picked itself for world_size=1. Correct answer, T=0 identical ×3.

L4 Production family + correctness blocked on L2-full

Qwen3-30B-A3B int4 (AWQ/GPTQ; AutoRound needs auto_round_lib, which has no Windows wheel) on one card; lap-8 bodies at 16k/30k; determinism.

L5 jobs/h after L4

SAT-L1 shape 8×16k; one instance, then one per card, vs production 3,358 jobs/h / 105 tok/s.

L6 Pipeline parallel over gloo stretch

Only if L5 says vLLM is more than a concurrency rung.

L7 Verdict —

D1 production engine · D2 concurrency rung omen-vllm (:8097, pin-only stanza, zero code) · D3 depth worker stays llama.cpp SYCL.
