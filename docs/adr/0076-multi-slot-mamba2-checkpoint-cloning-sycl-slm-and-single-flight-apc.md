# ADR-0076: Multi-Slot Mamba-2 Checkpoint Cloning, SYCL `BMG_G31` SLM Unlocks, and Single-Flight APC across the 3-Tier Fleet

- **Status:** Accepted and implemented (2026-10-24)
- **Date:** 2026-10-24
- **Deciders:** Derek, Claude / Codex / Gemini (Antigravity)
- **Related:** ADR-0034, ADR-0060, ADR-0061, ADR-0062, ADR-0075

## Context

After deploying `omen-nemotron-74b` (`NVIDIA-Nemotron-3.5-Bolt-74B-A9B-UD-Q4_K_XL` across Dual Intel Arc Pro B70 `SYCL0,SYCL1`), `am4-vllm` (`Qwen3.8-27B Dense` TP=2 across RTX 5070 + RTX 4070 Ti SUPER), and `:18097` (`jepa-router-v3` on Intel Arrow Lake NPU) under `bolt74-dense27` (ADR-0075), we conducted a 4-round empirical saturation and efficiency investigation (`c = 1..16`) culminating in the live **`AMUX-178` Tri-Agent (`Claude` + `Codex` + `Gemini`) `c = 8` full-door saturation wave** (`stream-claude-01`, `stream-claude-02`, `stream-codex-01`, and `Gemini` host telemetry monitor).

Driving 8 concurrent slots through the production HEARTH MCP door (`127.0.0.1:8710`) exposed five compound systems bottlenecks across the C++ SYCL kernels, `llama-server` recurrent state management, HEARTH prompt serialization and admission locking, AM4 `oxen-facade` / vLLM KV pool sizing, and the NPU context packager:

1. **Multi-Slot SYCL Decode Step-Down on `BMG_G31` at `c = 3..4`:** In `NVIDIA-Nemotron-3.5-Bolt-74B-A9B-UD-Q4_K_XL`, 255 of the 256 dense, Mamba-2 (`ssm_in`/`ssm_out`), Attention, MoE latent (`ffn_latent_down`/`up`), shared-expert, and LM-head matrices are `Q8_0` (156), `Q6_K` (94), or `Q5_K` (23), yet `reorder_vec_dot_shared_weights<T>::value` was enabled only for `Q4_K`, causing `mul_mat_vec_q_reorder_ncols` to re-load and unpack weights `ncols_dst` times per block. Furthermore, `ssm_conv.cpp` performed 64-bit `size_t` integer division/modulo 50 times per generated token.
2. **Mamba-2 Recurrent State Truncation, Destructive `server_prompt_cache::load`, and `6.50 GiB` PCIe Eviction Thrashing:** Unlike Transformer KV caches that truncate at arbitrary token indices, Mamba-2 recurrent states ($h_t$) evolve in-place and can only be restored at saved state checkpoints. Even when Turn-Boundary Checkpointing created a checkpoint at `last_user_pos`, upstream `llama-server` skipped saving it when `f_keep >= 0.5f` (`server-context.cpp:1606`), destructively erased `it_best` on the first `server_prompt_cache::load` (`server-task.cpp:1864`) so Slots `1..7` could not clone it, split the first user header at token 4 (`pos = 4`), and—because `kv_unified == false`—re-copied all 7 idle slots (`6.50 GiB`) from GPU VRAM to CPU RAM over PCIe (`2.42–2.65 s` stall) after every 8-slot wave.
3. **HEARTH Non-Delivery `request_doc` Prefix Divergence, Cold-Wave Stampede, and Lock Contention:** Non-delivery `submit_local_work` calls (`delivery = False`) serialized `json.dumps(request_doc, sort_keys=True)`, placing per-task `acceptance_criteria` and `intent` before `source_pack` and JSON-escaping all newlines (`\\n`, adding `+3,175` tokens per request and defeating prefix reuse). On non-Mamba vLLM seats (`am4-vllm`), splitting shared context into a 2-turn conversation broke vLLM's single-turn Automatic Prefix Caching (APC), while concurrent cold waves dispatched `N` redundant prefill passes before the cache was populated. Meanwhile, `ExecutionService.submit` held `self._lock` across `artifacts.put` (`fsync`), and `_submit_admitted` issued uncached `/tokenize` HTTP round-trips and `Path.glob` + `stat()` scans under lock.
4. **AM4 Concurrency Clamps, `/tokenize` Serialization, and KV Preemptions:** `am4-vllm` (`10.44.0.2:8090` / `:18094`) was clamped to `parallel_slots = 1` / `--max-num-seqs 2`, `oxen-facade.py` used `LISTEN 0 5` with uncached `72 ms` `/tokenize` round-trips, and `--gpu-memory-utilization 0.90` (`59,499` KV+Mamba tokens) suffered `3.0` preemptions during `4 × 26.4K`-token concurrent waves (`105.54 s` follower wall time).
5. **NPU Ping-Pong Stall, `[1, 256]` Padding, and `_encode_lock` Contention:** `:18097` (`jepa-router-v3`) padded short AST symbols (`<= 128` tokens) to `[1, 256]`, bypassed `/dev/shm/mechsuit-ast-arena` on `sourcemap.py` calls, and held `self._encode_lock` across NPU inference instead of only the `< 5 µs` LRU dictionary lookup.

## Decisions & Mechanisms

### 1. SYCL `BMG_G31` Kernel Unlocks (`ggml-org/llama.cpp#25356` + Round 2/4 Extensions)
- **SLM Weight & Activation Reorder for `Q8_0`/`Q5_K`/`Q6_K` at `ncols_dst = 2..4` (`ggml/src/ggml-sycl/vecdotq.hpp`):** Implemented `load()`, `load_activations()`, `apply()`, and `dot()` and enabled `reorder_vec_dot_shared_weights` + `reorder_vec_dot_shared_activations` across `Q8_0`, `Q5_K`, and `Q6_K`, eliminating redundant per-column global weight loads across 255 of 256 non-routed matrices in `Nemotron-3.5-Bolt-74B-A9B`.
- **`Q4_K` `rows_per_sg = 2` Gate (`ggml/src/ggml-sycl/mmvq.cpp`):** Gated `rows_per_sg = 2` on `nrows >= Q4_K_MMVQ_ROW_PAIR_MIN_NROWS` (`6272`) across `ncols_dst = 2, 3, 4`.
- **Dynamic Per-Layer MoE Density Gate (`ggml/src/ggml-sycl/ggml-sycl.cpp`):** `ggml_sycl_mt_max_tokens(n_expert, n_experts_used)` dynamically computes `std::min(64, (2 * n_expert) / n_experts_used)` (`53..64` tokens per layer across Nemotron-3.5-Bolt's heterogeneous `240..496` Puzzle NAS routed experts / `top-9`).
- **32-Bit `ssm_conv` & `ssm_scan` Decode Fast Paths (`ggml/src/ggml-sycl/ssm_conv.cpp`, `ssm_scan.cpp`):** Replaced software-emulated 64-bit `size_t` integer division/modulo in `ssm_conv.cpp` with 32-bit `uint32_t` index arithmetic, added a zero-division fast path for `n_t == 1` (decode) and `n_s == 1`, template-specialized `D_CONV = 4` with `#pragma unroll` + `sycl::fma`, and hoisted loop-invariant `A_warp[0]` in `ssm_scan.cpp`.
- **Measured Impact on Dual B70 (`omen-nemotron-74b`):**
  - `c = 3` decode: **`+235.7%` (`3.36x`, `17.9 -> 60.09 tok/s` wall / `85.25 tok/s` pure decode)**
  - `c = 4` decode: **`+203.8%` (`3.04x`, `22.8 -> 69.27 tok/s` wall / `98.62 tok/s` pure decode)**
  - `c = 1` warm decode: **`41.22 tok/s`** (`24.26 ms/tok`)
  - `c = 8` decode: **`85.57 tok/s` wall decode / `122.76 tok/s` pure decode (`15.22 tok/s/slot`)**

### 2. `llama-server` Multi-Slot Mamba-2 Checkpoint Cloning & PCIe Eviction Elimination (`server-context.cpp`, `server-task.cpp`)
- **Non-Destructive Multi-Slot Checkpoint Cloning (`tools/server/server-task.cpp`, `server-context.cpp`):** Patched `get_available_slot` to set `update_cache = true` whenever `!ret->prompt.checkpoints.empty() && f_keep < 1.0f`, and patched `server_prompt_cache::load` to clone `it_best->prompt.clone()` and LRU-promote `it_best` (`states.splice(states.end(), states, it_best)`) instead of erasing it, allowing all 8 slots in a concurrent wave to share a single warm Mamba-2 Turn-1 checkpoint.
- **PCIe Eviction Carousel Elimination (`tools/server/server-context.cpp`):** Added `slot.prompt_cached` tracking (`reset()` / `prompt_clear()` set `false`, `prompt_save()` sets `true`) and gated the post-launch `cache_idle_slots` sweep on `params_base.kv_unified`, eliminating the **`6.50 GiB` / `2.42–2.65 s` PCIe VRAM-to-RAM eviction stall** after 8-slot Mamba-2 waves (`0` idle-slot dumps, `0` FIFO cache evictions).
- **Eliminating `<64`-Token First-User-Header Splits (`pos = 4`) & Duplicate `n_swa == 0` Checkpoints (`tools/server/server-context.cpp`):** Skipped `spans.is_user_start` batch breaks when `pos < 64` and omitted duplicate `4 + n_ubatch` checkpoints when `n_swa == 0`, reducing per-slot checkpoint memory by **47% (`928.8 MiB -> 330–495 MiB`)**, eliminating 1 full 74B prefill pass per cold prompt, and cutting cross-slot checkpoint cloning latency to **`151 ms` (`0 ms` when already in slot VRAM)**.
- **Checkpoint-Aware Effective LCP (`tools/server/server-context.cpp`, `server-task.cpp`):** Added `get_slot_eff_lcp` / `get_prompt_eff_lcp`, guarded busy slots when `task.id_slot != -1`, and required `f_sim_cur > f_sim_base` before copying from CPU `prompt_cache` over PCIe.
- **Runtime Guard:** Preserved `SYCL_CACHE_PERSISTENT=0` and `GGML_SYCL_DISABLE_GRAPH=1` in `start-nemotron-74b.sh` (`SYCL_CACHE_PERSISTENT=1` triggers a Level Zero `SEGV` at `llama threadpool init` on dual `BMG_G31`).

### 3. HEARTH Turn-Boundary Checkpointing (`Shape 6`), Non-Mamba vLLM APC Prefix Ordering & Zero-Overhead Single-Flight Cold-Prefix Coalescing
- **Unified Context-Pack Splitting (`Shape 1..6`) & `carry` Checkpointing (`hearth/adapters/openai_server.py`, `hearth/toolsurface/inference.py`):** Extended `split_shared_context_pack` (using `rfind` for `SHARED_PACK_END_MARKERS` to avoid docstring false matches) and `checkpoint_messages_list` across all 5 delivery pack shapes, `_run_delivery_carry` (`work`, `check`, `attach`), and **`Shape 6` non-delivery `LocalWorkService` `request_doc` payloads**. Unescaping `source_pack` removes `3,175` tokens of `\\n` escaping (`28,427 -> 25,252` tokens) and places the invariant repository pack in Turn 1 (`25,178` tokens) and the per-task `intent` + `acceptance_criteria` in Turn 2 (`74–76` tokens) for Mamba-2 targets (**`99.70%` cache hit across all 8 slots in `11.25 s`**, down from `>165 s` — **`>14.7x` faster**; `c = 4` wave `139.65 s -> 7.03 s`, **`19.86x` faster**).
- **Non-Mamba vLLM APC Prefix Ordering (`hearth/adapters/openai_server.py`):** For non-Mamba vLLM backends (`am4-vllm`, `omen-router`), reorders `Shape 3 / 5 / 6` prompts into a single-turn prefix-first layout (`f"{shared_context_pack}\n\n{task_instruction}"`) so vLLM Automatic Prefix Caching (`--enable-prefix-caching`) matches all shared `1,568`-token Mamba-aligned blocks from token 0 (**`94.92%` follower block hit rate**).
- **Zero-Overhead Single-Flight Cold-Prefix Coalescing (`hearth/adapters/openai_server.py`, `hearth/toolsurface/inference.py`):** `begin_single_flight_prefix` coordinates concurrent cold-prefix waves: Caller 1 (`leader`) dispatches immediately with zero extra warmup requests while Callers `2..N` (`follower`) wait on Caller 1's `threading.Event` and then fire in parallel against the populated prefix cache (`55.90 s -> 30.35 s` cold 4-slot wave; **`6.03 s` warm 4-slot wave, `9.27x` faster**).
- **Admission Tokenizer Digest Cache, Lock-Free Artifact `fsync` & O(1) Terminal Manifest Tracking (`hearth/localwork/service.py`, `hearth/execution/service.py`):** Added `_TOKEN_COUNT_CACHE` keyed by `(endpoint, model, prompt_digest)`, moved `self.artifacts.put(...)` (`fsync`) outside `ExecutionService._lock`, moved `SourceMap` + NPU AST slicing outside `_submit_lock`, and replaced `Path.glob("work_*/work-manifest.json")` + `stat()` inside `_submit_admitted` with `os.scandir` + O(1) terminal manifest tracking.

### 4. AM4 `oxen-facade.py` & `am4-vllm` KV Cache Expansion (`10.44.0.2:8090` / `:18094`)
- **Unlocked `c = 8` Concurrency & Expanded KV+Mamba Pool (`run-vllm-canary.sh`, `alias-backends.json`, `backends-linux.toml`, `lab-configurations.toml`):** Raised `am4-vllm` concurrency from `parallel_slots = 1` / `--max-num-seqs 2` to **`parallel_slots = 8` / `--max-num-seqs 8`** and tuned `--gpu-memory-utilization 0.912`, expanding the KV+Mamba pool by **`+26.1%` (`59,499 -> 75,021` tokens / `~57` blocks of `1,568` tokens)** while preserving the exact `>1.1 GiB` CUDA workspace headroom required by RTX 5070 (`sm120` Blackwell) `marlin_gemm` during `2,048`-token chunked prefill passes (`0.92+` triggers CUDA OOM during prefill).
- **Low-Latency `oxen-facade.py` (`10.44.0.2:8090`):** Set `LISTEN 0 128` (`request_queue_size = 128`), `protocol_version = "HTTP/1.1"`, `disable_nagle_algorithm = True`, `5.0 s` `alias_status` TTL cache, SQLite `journal_mode=WAL` on `hermes-attempts.sqlite`, and a 64-entry SHA-256 + content-bag `/tokenize` cache (**`72.06 ms -> 3.45 ms`, `20.9x` faster**, eliminating 100% of redundant `guard_context` `/tokenize` round-trips during `/v1/chat/completions`).
- **Measured Impact on `am4-vllm`:**
  - Compact AST-sliced `c = 8` waves: **`96.29 tok/s` cold decode (`2.63x` vs `c = 1`)** and **`257.65 tok/s` shared-prefix decode (`2,683.4` total tok/s, `5.96 s` wall, `6.60x` vs `c = 1`)**.
  - Full `4 × 26,430`-token (`105,720`-token) wave: 3 concurrent followers completed in **`2.99 s` total wall time (`2.88 s/req`, down from `105.54 s` in `AMUX-178` — `35.3x` faster)** with **`94.92%` prefix cache hit rate (`16 / 16` blocks per follower)** and **`0.0` preemptions (down from `3.0`)**.

### 5. Intel Arrow Lake NPU + `/dev/shm` AST Slicing (`jepa-router-v3.service` `:18097`, `sourcemap.py`, `daemon_v3.py`)
- **Dual-Shape `[1, 128]` / `[1, 256]` `ov.AsyncInferQueue(jobs=2)` (`shm_npu_arena.py`, `daemon_v3.py`):** Replaced manual 2-slot ping-pong with `ov.AsyncInferQueue(compiled_model, jobs=2)` (`99.96%–99.98%` NPU hardware duty cycle across `NPU_MAX_TILES = 2`) and added `[1, 128]` static compilation for short AST symbols, lifting NPU throughput from `128.7 emb/s` to **`303.74–331.3 emb/s` (`3.26x` end-to-end speedup)**.
- **`/dev/shm/mechsuit-ast-arena` Content-Addressed Caching & Parallel Keep-Alive (`sourcemap.py`, `context_packager.py`, `hybrid_router.py`):** Wired `sourcemap.py` to `/dev/shm/mechsuit-ast-arena` (`ShmAstArena`), added persistent HTTP/1.1 keep-alive with `TCP_NODELAY`, parallelized multi-file AST slicing across `ThreadPoolExecutor(max_workers=8)`, and cached BM25/hubness indices (`@lru_cache(maxsize=256)`), cutting 4-file `SourceMap` slicing to **`29.63 ms`** (`7.52 ms` fully warm, `42,701.8 chunks/s`) and cold-process `pack_files_for_intent` from `1,226.51 ms -> 48.26 ms` (**`25.4x` cold-process speedup**).
- **Narrowed `_encode_lock` (`daemon_v3.py`):** Scoped `self._encode_lock` to the `< 5 µs` LRU dictionary lookup instead of the full NPU inference pass, cutting `c = 8` concurrent burst `/rank_candidates` tail latency from **`279.65 ms -> 107.01 ms` (`p50 = 70.33 ms`, `2.6x` lower tail latency)**.

## Consequences

- **Positive:** Both heavy tiers (`omen-nemotron-74b` on Dual B70 and `am4-vllm` on AM4 TP=2) now sustain full `c = 8` concurrent waves (`16` combined deep slots across the two machines) with near-100% shared-prefix cache reuse (`99.70%` Mamba-2 checkpoint hit on OMEN in `11.25 s`; `94.92%` APC block hit on AM4 in `2.99 s`), `0` PCIe idle-slot evictions, `0.0` KV preemptions, and sub-30 ms NPU+`/dev/shm` AST context packaging.
- **Verification & Drift:** All `232/232` unit tests (`adapter`, `delivery`, `localwork`, `execution`, `ops`, `toolsurface`), `tools/ops/sizing_map.py --check --live` (`304 settings, 0 violations`), and `tools/ops/host_config.py --check` (`78/78` host config pairs byte-identical, `0` drift) pass.
