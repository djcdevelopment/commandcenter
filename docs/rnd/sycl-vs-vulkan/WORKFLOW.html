SYCL vs Vulkan on the B70s

An R&D workflow: is there a faster engine under the fleet? Designed 2026-09-19. Source of truth is WORKFLOW.md beside this page; the register is docs/rnd-log.md.

Scope (Derek): Windows-only, llama.cpp SYCL via oneAPI. A winner may replace anything, production omen-arc included. Open-ended until the ladder is complete; written verdict either way. vLLM is parked with a reopen condition (bottom).
Scoreboard: total throughput × accuracy of work completed on local hardware, B70s kept decoding — not per-request latency.

Why now

Every number shaping decisions today is a Vulkan-on-Xe2 number from one engine (the knee fork, build 52 / 60cdd25): the dual-B70 prefill knee 609 → 443 → 117 tok/s from 16k to 119k, decode 4.9 tok/s at 119k with aggregate capped near 6, production's 105 tok/s and 3,358 jobs/h at -np 8. llama.cpp PR #25222 (2026-07-15) put oneDNN/XMX flash attention into the SYCL backend and reports 4.26× prefill at 80k on a B70 — exactly where Vulkan collapses. Against it: the one same-card comparison has Vulkan ahead on 8-stream decode; SYCL on Battlemage carries open correctness bugs. Nothing measures both backends' newest kernels on the same card at the same depth. That gap is the experiment.

The decision chain

  • D1 — production's engine. SYCL replaces the Vulkan fork only if it clears production's own bar on production's shape: ≥ 105 tok/s single-stream, ≥ 3,358 jobs/h at -np 8 × 16k, dual-split MoE loads, T=0 answers equal to Vulkan's, Q4 200-row CV ≤ ~2.3%, zero TDR/WHEA soak. Any miss → not the default.
  • D2 — MemSplice's shape and the long-task route. If SYCL prefills the 27B near 500 tok/s at 120k on one B70, disaggregation drops from 9.8× to ~3× and the route threshold moves. If SYCL moves the decode ceiling at depth, the depth economics change — the number nobody has published.
  • D3 — the depth specialist rung (omen-arc-27b). Engine choice is per rung: SYCL can win here and lose D1.
  • D4 — parked upstream work. The across-layouts KV patch is backend-agnostic and stays. The Vulkan FA rebase (#24406) is measured first so every comparison is best-vs-best.
  • D5 — the door. Any candidate seat is a pin-only [[backend]] stanza — zero code — so the bake-off lands on the ledger.
  • D6 — the OS. Untouched. vLLM reopens only on native Linux or a B70 back in AM4; WSL2 is not a path on this host.

Results

L0 — done (2026-09-19). vLLM parked (Linux-only; WSL2 dual-Arc bridge kernel-dead on this host per ember ADR-0012; no XPU KV connector; no cross-vendor P/D). SYCL in on the strength of PR #25222, gated by #21893 / #20169 / #19276 correctness bugs. Prior attempts re-dated to May–June 2026.

L1b — checked. Intel's Vulkan Xe FA kernels (#24406) are not on upstream master as of 60081bb; the Vulkan side of every comparison is production's build 52.

L1 — done (06:00Z). oneAPI was already installed at a custom dir (2026-09-08); oneMKL + oneDNN added via the installer's modify action; Intel's setvars.bat fails on this box (cwd lookup after the VS init) — sycl-env.cmd replaces it. sycl-ls: level_zero:0/1 = B70s, :2 = iGPU. The fork builds SYCL at the production commit (build 52 / 60cdd25, oneDNN + oneMKL linked); --list-devices shows SYCL0/SYCL1 = B70. Ladder open; L2 next, inside the maintenance window.

L2 — done (06:15Z). One B70. 27B: SYCL prefill 810 tok/s vs 375 at 16k (2.16×), decode 12.2 vs 15.3, generation byte-identical. MoE: SYCL prefill 2.3× at 16k but non-deterministic at T=0 (four runs, four answers; DISABLE_OPT no help); Vulkan deterministic. llama-bench pp512/pp2048/tg128 — 27B 892/1111/21.5 vs 756/703/23.9; MoE 1498/1880/111 vs 2383/2170/122.

L3 — done (06:35Z). Production's MoE dual -np 8 shape loads on SYCL with the split honoured; single-stream 104.9 tok/s (parity). -sm tensor loads and runs (Vulkan cannot); no gain at ≤16k.

L4 — done (07:05Z). SYCL dual 27B prefill 813 / 817 / 736 / 614 tok/s at 16k / 30k / 60k / 119k vs Vulkan 609 / 443 / — / 117 — the knee is gone, 5.2× at 119k. Decode within 8–13% of Vulkan. Tensor split at 119k decodes 6.74 tok/s (+38% over Vulkan) with identical output. D2: MemSplice at 119k is 1.9× SYCL-local, not 9.8×. D3: depth specialist → SYCL tensor split.

L7 — done (07:20Z). The CUDA-made 119k q4_0 state restored into a SYCL seat (1.2 s) and decoded correctly — the slot state is vendor- and backend-agnostic.

L4b — 256k (07:25Z). The 27B at 262,144 loads on both B70s (2.3 GB KV per card). SYCL alone: 248,515 tokens in 552.9 s (9.2 min), decode 2.24 tok/s. Hybrid AM4 119k + B70 tail: 433 s (7.2 min); the deep tail at 366 tok/s is the wall. Bar was ~3 min; the path there is a smaller quant on AM4 so the NVIDIA pair prefills the whole 256k (~3.5 min).

L4c — f16 KV (08:25Z). The SYCL kernel selector makes decode TILE/VEC with a per-step dequant for quantized KV. With f16 KV: decode at 119k 9.41 tok/s (q4_0 4.24, Vulkan 4.9), at 248k 5.89 (q4_0 2.24). Prefill unchanged. -ub 4096 -b 8192 adds +19% prefill. Best 248k: 8.5 min, decode 5.89 tok/s — from 9.2 min / 2.24 at the start of the night.

L4d — decode levers (10:22Z). f16 + tensor split does not stack (+9%). MTP (draft-mtp, n_max 3) on the layer-split f16 seat: 119k decode 19.98 tok/s (9.41 without), 248k 14.37 tok/s (5.89 without), output identical at T=0, correct answers. n-gram drafting: 6.30 tok/s, worse than none. Tonight's arc at 248k on the same cards: 2.24 → 5.89 → 14.37 tok/s. Mid-lap: an MTP seat at -ub 4096 overfilled a card and WDDM spilled 24.8 GB to system RAM — gpu-mem-gate.ps1 now runs before every benchmark; and a runaway agent grep over the models directory took production down for 20 min (disk, not GPU — recorded).
