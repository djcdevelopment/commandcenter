Levers for 256k Qwen3.8-27B

What exists on the fleet and in the fork that could move a 256k run — inventoried 2026-09-19, source of truth LEVERS-256K.md. Nothing here is a "no": each item is measured, untested, or closed with a reopen condition.

Where we stand: both B70s, SYCL, layer split, f16 KV, -ub 4096: 248,515 tokens in 8.5 min (485 tok/s), decode 5.89 tok/s, correct answer. AM4+B70 hybrid 7.2 min (q4_0). Bar: ~3 min.

Hardware that exists

  • OMEN: 2× Arc Pro B70 32 GB; 285K 24C; 127 GB RAM; Intel iGPU (SYCL2, 69 GB shared); NPU (Intel AI Boost); Marvell AQtion 10GbE (linked at 1G — far end is 1G) + I226-V 1G; WSL2 + Docker Desktop; NVMe KV parking.
  • AM4: RTX 4070 Ti 12 GB + RTX 5070 12 GB (CUDA 13.2); 5900X; 30 GB RAM; I211 1 GbE; oneAPI 2026.0, no Intel GPU.
  • fx99: RTX 2070 SUPER 8 GB; Ollama qwen2.5-coder:7b; monitoring + keep-alive + bastion; LAN 1G.
  • Wires: OMEN↔AM4 direct 1 GbE (112 MB/s); LAN 1G to fx99.

Software that exists

  • The knee fork @ 60cdd25 + across-layouts restore: Vulkan (production), SYCL (oneDNN/oneMKL XMX), CUDA on AM4. Backends present but OFF: ggml-rpc, ggml-openvino (CPU/GPU/NPU), ggml-opencl.
  • Flags in this build: -sm layer|tensor, -ot, -nkvo, -dev, --fit, --cache-ram, --ctx-checkpoints, -kvu, speculative draft-mtp | eagle3 | dflash | ngram-*, -md, -devd (draft device).
  • Models: 27B Q4_K_M + mtp-Qwen3.8-27B-Q4_0 + mmproj; Flash-Next MTP; 30B-A3B; 70B; others.
  • MemSplice (save → wire → restore, vendor- and backend-agnostic; drivers), sycl-*.cmd, build recipes.
  • OpenVINO 2026.3 venv seeing CPU, GPU.0, GPU.1, GPU.2, NPU; GenAI not installed (Qwen3.8-27B needs 2026.4+; one community number: 13.9 tok/s short decode on a B70).
  • HEARTH door / control plane / scheduler; upstream PR #24406 pending; our PR parked.

Limit A — deep prefill (485 tok/s at 248k; bar ~1,400)

A1 Four-GPU RPC pipeline untested

AM4's pair + the B70s as one layer-split model over the direct link. AM4's 128k ceiling vanishes; prefill scales with pipeline depth (~2× → ~4 min); no wire step, no restore.
cost: two GGML_RPC=ON rebuilds + a lap · the structural lever

A2 AM4 carries all 256k untested

IQ4_XS/Q3_K_M on AM4 fits 256k q4_0 KV on the 12 GB pair → ~1,200 tok/s ≈ 3.5 min, then ship. Ship size is the catch (q4_0 5 GB vs f16 16 GB).
cost: a ~15 GB download · pairs with A3

A3 10 GbE hardware

OMEN already has the 10G port; AM4 needs a 2.5/10 GbE NIC. Wire 2.5–10×: an f16 256k state ships in ~16 s.
cost: a $30–100 part

A4 Two-card independent prefill policy

SYCL single-card prefill ≈ dual (810 vs 813 at 16k) → two prompts on separate cards ≈ 2× aggregate; decode together on tensor split.
cost: none · job-shop routing

A5 Batch shape spent

-ub 4096 -b 8192 +19 %, next step +3 %.
done

A6 Vulkan #24406 upstream

Intel's Xe FA kernels for Vulkan; not merged as of 60081bb; build-vk-next.cmd ready.
cost: wait

A7 OpenVINO GenAI on the B70s untested

Paged attention, continuous batching, KV compression; depth unmeasured; short decode 13.9 tok/s (below llama.cpp).
cost: venv bump to 2026.4+, re-export · only if A1–A3 stall

Limit B — decode at depth (5.89 tok/s at 248k)

B1 f16 KV on tensor split untested

Tonight's two decode gains were measured separately; they may stack.
cost: one relaunch

B2 MTP untested at depth

--spec-type draft-mtp -md mtp-Qwen3.8-27B-Q4_0.gguf. A 4-token verify pays the attention read once; nightshift saw 2.1× on Vulkan at short context.
cost: one flag · check T=0 equivalence

B3 n-gram speculation untested

--spec-type ngram-cache: drafts from the prompt's own repetition, no draft model. Source-code prompts repeat a lot.
cost: one flag, zero memory

B4 oneDNN for decode fork patch

Lower the ≥32-query-token gate for f16 KV at long KV. Unknown whether fused SDPA beats VEC at q=1.
cost: one line + rebuild

B5 Draft model on iGPU/CPU/NPU untested

-md <small> -devd SYCL2 (or CPU; NPU via ggml-openvino is the exotic route). Keeps B70 VRAM for KV.
cost: a ~1 GB draft GGUF download

B6 q8_0 KV untested

Middle ground between q4_0 memory and f16 decode speed.
cost: one relaunch

Exists, but does not move this objective — with the reopen condition

  • NPU: reachable via OpenVINO GenAI and via ggml-openvino (GGML_OPENVINO_DEVICE=NPU); static graph, stateless, ≤8B-class, 256-token prefill chunks, no parallel sequences. Could host a draft model (B5). Reopen: a draft-device path that measurably lifts B70 decode, or NPU hardware with real bandwidth.
  • fx99: cannot hold the 27B; under A1 it can carry a few layers as a third RPC host over the LAN (~10 % more prefill capacity, pipeline paced by its slowest stage). Reopen after A1 proves out on four GPUs.
  • iGPU: slowest pipeline stage; plausible draft device (B5). CPU: draft device, -ot target. WSL2/Docker → vLLM: dual-Arc bridge dead; single-Arc untested since June. ggml-opencl: Adreno-focused, untested on Xe2. Flash-Next: different model. llm-scaler: Linux only.

Recommended order

  1. B1 + B2 + B3 in one window (~30 min) — decode at depth is where the momentum is.
  2. A1 the four-GPU RPC pipeline (~1 h incl. builds) — the only lever that changes the prefill ceiling.
  3. A3 + A2 — a NIC for AM4 and an IQ4_XS 27B: the AM4-alone ~3.5-minute path with a 16-second ship.
  4. B4 and A7 only if 1–3 leave the bars unmet.
